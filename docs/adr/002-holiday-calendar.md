# ADR-002: ปฏิทินวันพิเศษ ขอบเขตตามเมือง และวันปิดร้าน

- สถานะ: Accepted
- วันที่: 2026-11-02

## บริบท
Generator ปรับจำนวนบิลรายวันด้วยตัวคูณตามวันพิเศษ (`config/business.yaml` → `seasonality.date_range`)
ร่างแรกใช้วันที่เต็มที่ระบุปีไว้ทุกรายการ จึงต้องแก้ config ทุกปี และถ้าลืมแก้ วันพิเศษของปีใหม่จะหายไปโดยไม่มีอะไรเตือน

วันพิเศษเปลี่ยนตามปีไม่เหมือนกัน:
- วันที่ตายตัว (วาเลนไทน์): ตรงวันเดิมทุกปี
- วันหยุดราชการ: วันที่ตามจันทรคติเลื่อนทุกปี (มาฆบูชา 2026-03-03, 2027-02-21) และมีวันหยุดชดเชย
- ปฏิทินธุรกิจ (ปิดเทอม, ตรุษจีนในฐานะเทศกาลขายของ): คนเป็นผู้ตัดสินใจทุกปี

## ทางเลือก
1. **ระบุปีทุกรายการ**: เรียบง่ายที่สุด แต่ต้องแก้ทุกรายการทุกปี และเขียนวันหยุดชดเชยเองแล้วพลาดได้ง่าย
2. **เขียนกฎวันหยุดเอง**: ไม่ต้องเพิ่ม dependency แต่การคำนวณวันตามจันทรคติและวันชดเชยซับซ้อน และเป็นงานที่ไม่ใช่เป้าของโปรเจค
3. **Tagged union `type` + library `holidays`**: แยกกฎตามพฤติกรรมของวัน ส่วนวันหยุดราชการให้ library คำนวณ

## ตัดสินใจ
เลือก **3** โดย `date_range` แต่ละรายการมี `type` เป็นค่าใดค่าหนึ่งต่อไปนี้:
- `public_holiday`: ใช้ `holidays.Thailand` (pin `holidays >=0.107,<0.108`)
- `annual`: `start`/`end` เป็น `"MM-DD"`
- `dated`: `start`/`end` เป็น `"YYYY-MM-DD"`

ตัวคูณของทุกรายการที่ตรงกับวันนั้นจะถูกคูณรวมกันทั้งหมด (รวมกับ `day_of_week` ด้วย)
แต่ละรายการมี `cities` ได้ (ไม่บังคับ) เพื่อจำกัดให้ใช้กับเมืองนั้นๆ ถ้าไม่ใส่จะใช้กับทุกสาขา
เลือกผูกกับเมือง ไม่ใช่สาขา เพื่อให้สาขาใหม่ได้พฤติกรรมของเมืองไปทันทีโดยไม่ต้องแก้ config เพิ่ม

วันที่ร้านปิดเป็น**ข้อเท็จจริงของสาขา** ไม่ใช่ตัวคูณ จึงเก็บไว้ที่ `branches[].closed`
(`weekdays` + `dates` ที่ใช้รูปแบบ type เดียวกับ date_range) วันที่ปิดคือไม่มีบิลเลยทุกช่องทาง และชนะตัวคูณทุกตัว

## ผลที่ตามมา
- รายการ `public_holiday` และ `annual` ใช้ได้ทุกปีโดยไม่ต้องแก้ config (ตรวจแล้วกับปี 2027 รวมถึงวันชดเชยมาฆบูชา 2027-02-22)
- **ยังมีงานประจำปี 2 อย่าง**: (1) เพิ่มรายการ `dated` ของปีใหม่ (2) อัปเวอร์ชัน `holidays` เพื่อรับวันหยุดพิเศษที่รัฐประกาศเพิ่ม เวอร์ชันถูก pin แบบ minor จึงต้องอัปเองด้วย `poetry update holidays`
- ผลของวันพิเศษต่างกันตามเมืองได้ เช่น สงกรานต์ กรุงเทพ ×0.40 และเชียงใหม่ ×1.20 (ก่อนคูณกับวันหยุดราชการและช่วงปิดเทอม)
- กฎคูณทั้งหมดคาดเดาได้ง่าย แต่คนตั้งตัวเลขต้องคิดผลคูณรวมเอง ใน config จึงมีคอมเมนต์ผลรวมกำกับไว้
- ไม่ใช้ `multiplier: 0` แทนการปิดร้าน เพื่อให้เขียน DQ test "ไม่มีบิลในวันที่ร้านปิด" ได้ และให้ reconciliation ตรวจเงินที่โอนเข้ามาในวันที่ร้านปิดได้
- Loader ต้องตรวจ `type` ที่ไม่รู้จัก, รูปแบบวันที่ และค่าใน `cities` ที่ไม่ตรงกับ `cities[].city_id` แล้ว error ทันที
- ถ้าใส่วันหยุดราชการ (เช่น สงกรานต์) ลงใน `annual` ด้วย จะถูกคูณซ้อนกับ `public_holiday` ต้องตั้งตัวเลขโดยคิดเรื่องนี้ไว้แล้ว

**ทบทวนเมื่อ**: ต้องการตัวคูณต่อสาขา (ไม่ใช่ต่อเมือง), การคูณซ้อนกันเริ่มทำให้ตั้งตัวเลขยาก (ให้พิจารณากฎ override) หรือย้ายปฏิทินไปไว้ใน `dim_date` ของ dbt (M2)
