# ADR-004: การโหลด config และการสุ่มข้อมูลจำลอง

- สถานะ: Accepted
- วันที่: 2026-11-04

## บริบท
Generator ต้องอ่าน config ที่คนเขียนมือ (พิมพ์ผิดได้) แล้วสร้างบิล 12 เดือนที่ deterministic
DoD ของ M1 กำหนดว่าเพิ่มสาขาได้โดยแก้ config อย่างเดียว และ backfill ใน M6 ต้องได้ partition เดิมทุกครั้ง
ส่วนข้อเท็จจริงทางธุรกิจ (สาขา เมนู ราคา GP) กับพฤติกรรมจำลอง (ลูกค้าซื้อกี่ชิ้น ยกเลิกบ่อยแค่ไหน) เปลี่ยนด้วยเหตุผลต่างกัน

## ทางเลือก
**ตรวจ config**: (1) dict + เช็คเอง (2) dataclass (3) pydantic v2
**ที่อยู่ของพฤติกรรมจำลอง**: (1) ใส่ใน `business.yaml` (2) แยก `simulation.yaml`
**seed**: (1) RNG ตัวเดียวทั้งโปรแกรม (2) RNG ต่อ `(branch_id, date)` (3) RNG สองระดับ วัน + บิล
**จำนวนบิลต่อวัน**: (1) ปัดเศษค่าคาดหวัง (2) Poisson

## ตัดสินใจ
- **pydantic v2** (`extra="forbid"`, `frozen=True`) ตรวจทุกอย่างที่ boundary: ชนิด, ช่วงค่า, id ซ้ำ, FK ข้าม entity
  เงินเป็น `Decimal` quantize 2 ตำแหน่ง · weight/ความน่าจะเป็นของการจำลองเป็น `float` ได้เพราะไม่ใช่เงิน
- `tests/` import `generator` ผ่าน `[tool.pytest] pythonpath = ["."]` (ไม่ทำเป็น package)
- **แยก `config/simulation.yaml`** ตรวจ FK กับ `business.yaml` ผ่าน `model_validate(..., context=)`
  ทุก `channel_id` และ `menu_id` ต้องมีค่าในไฟล์นี้ ไม่มี default
- **seed แบบ 2**: `random.Random(f"{seed}|{branch_id}|{date}")` ใช้ RNG เดียวสุ่มทุกอย่างของวันนั้น
- **Poisson** ผ่าน Poisson process อัตราคงที่รายชั่วโมง (ระยะห่างแบบ exponential):
  ได้ทั้งจำนวนบิล ~ Poisson(ค่าคาดหวัง) และเวลาที่กระจายตาม `hourly_weight` ในขั้นเดียว ไม่ต้องเพิ่ม numpy
- `order_id` = `{branch_id}-{YYYYMMDD}-{seq:04d}` เรียงตามเวลา · `platform_order_ref` = `{prefix}-{64 บิตสุ่ม}`

## ผลที่ตามมา
- config ผิดพังตอนโหลดพร้อมบอกตำแหน่ง ไม่ใช่พังกลางการ generate
- เพิ่มสาขา/ขยายช่วงวันแล้ววันเดิมได้ข้อมูลเดิมทุกไบต์ · generate ขนานต่อสาขาหรือต่อวันได้
- **ยอมเสีย**: เปลี่ยนลำดับการเรียก RNG ภายในวัน (เช่น เพิ่มการสุ่มในตะกร้า) แล้วบิลของทุกวันเปลี่ยน
- `order_id` ไม่มีวันชน (ได้จากการนับ) แต่บอกจำนวนบิลต่อวันได้ · ref ของ platform โอกาสชน ≈ 10⁻⁹ ต่อปี
- จำนวนบิลมี noise ตามธรรมชาติ (SD ≈ √λ ≈ 17 ที่ λ = 280) ให้ anomaly/variance ใน M5, M7 มีของจริงให้จับ
- pure Python: ทั้งปี 5 สาขา ≈ 417k บิล รวมเขียน Parquet ใช้เวลาราว 7 วินาที

**ทบทวนเมื่อ**: ต้องการแก้ logic ตะกร้าโดยบิลเดิมไม่เปลี่ยน (ไปทาง seed สองระดับ), ข้อมูลใหญ่จน pure Python ช้าเกิน,
หรือพฤติกรรมต่างกันตามสาขา/ช่องทาง (เช่น ตะกร้า delivery ใหญ่กว่าหน้าร้าน)
